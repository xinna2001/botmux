# TraeX Auto 模型池

实验功能默认关闭，仅用于 Botmux 直接管理的 TraeX 终端会话。Dashboard → Bot 配置 → Agent 配置中开启后，保存 `model: "auto"` 和 `traexAutoModel`；实际传给 TraeX 的是池中具体模型，虚拟 `auto` 不进入 CLI。

```json
{
  "model": "auto",
  "traexAutoModel": {
    "enabled": true,
    "models": ["gpt-5.6-sol", "gpt-6-astra", "gpt-5.6-terra"],
    "modelSettings": {
      "gpt-5.6-sol": { "reasoningEffort": "high", "modelBackendVariant": "max" },
      "gpt-6-astra": { "reasoningEffort": "xhigh", "modelBackendVariant": "standard" },
      "gpt-5.6-terra": {}
    },
    "queueTimeoutMs": 30000,
    "reselectPerTurn": false,
    "switchCooldownMs": 60000
  }
}
```

模型池无数量上限。每个模型下方独立选择思考强度与上下文；Standard / Max 及容量、可用思考档位来自 TraeX 实时目录。空设置表示使用该模型默认；旧版仅字符串池继续兼容共享设置。切换与启用下一回合恢复首选时同时更新两项覆盖，卡片显示当前档位。

页面只显示「模型排队时，自动切换到模型池中其他不排队的模型。」，详细规则在问号的 hover/focus 提示中。该说明表达自动寻找可用模型的目标；负载快照不保证一次尝试即可免排队。

未保存模型池编辑同步写入按 Bot 隔离的浏览器草稿；刷新和目录重新加载不得覆盖草稿。模型池旁提供「保存并生效」，成功写入服务端后清除草稿；保存失败仍保留编辑并显示错误。新增模型默认选最大支持上下文及对应最高兼容思考强度，手动较小上下文与该档位最高强度组合有效。

首项是首选模型。新话题从首项开始，同话题后续输入默认沿用已选模型；默认关闭的「话题内每轮重新择优」开启后，每条新输入才重新从首项开始。后续输入按回合顺序处理。持续容量排队达到阈值后，只读调用 TraeX `app-server` 的 `initialize`、`model/list`，不创建 thread、不发送推理输入。按配置顺序检查当前项后面的模型，选择首个 `businessMetadata.load.load_percent <= 100` 的模型；第二项 100%、第三项 100% 或 50% 都应先选第二项。负载缺失时先按顺序尝试未知项，不假定为零，也不越过偏好更高的未知项。

负载只是可用性线索，不保证免排队。选中备选后如果实际排队，连续确认一秒就刷新负载并继续检查后面的模型，不再等待完整 30 秒或 60 秒切换间隔。备用模型连续工作两秒后结束本次搜索；之后再次排队按正常阈值处理。本次搜索只向后尝试，不返回前项重新探测；仅当后项均显示高负载或池已耗尽时，完整负载快照才用于选择池内最低者，同值按配置顺序选择，随后保持等待。最终等待状态默认跨输入保留；启用每轮重新择优才在新输入时解除。已选模型、最终等待状态、已交付目录指纹持久化在 Session JSON 中，恢复时严格核对原生会话 ID 和模型池策略签名。

读取不到负载时，按配置顺序有限尝试。池耗尽后比较本轮十分钟内最近的真实队列名次，只额外切换一次到最靠前者并保持等待；缺失名次时留在当前模型。`51s` 是已等待时长，`position 1590` 是队列名次，二者均不是精确剩余等待时间。不同模型吞吐不同，负载最低和队列最短都只是可观测选择依据。

排队阈值默认 30 秒，不同排队事件的切换间隔默认 60 秒，均允许 5–300 秒。同一次备用搜索跳过完整阈值和切换间隔；启用新回合恢复首项时也优先于缓冲。切换通过原生 exact resume 保留原会话，退休原输入的传输重放记录，只注入一条继承原回合身份的继续提示。没有精确原生会话 ID 时不自动切换，禁止降为全新会话。

同一话题多轮切换模型仍续接同一个原生会话 ID，已有用户问题、回复及工具记录由 TraeX 恢复。共享的是可见会话记录，不能迁移模型未写入记录的内部思考，也不能保证不同模型理解完全相同。长历史遵循 TraeX 原生压缩规则；较小上下文档位可能触发更早压缩。模型缓存与历史连续性分开，换模型可能重新处理上下文并增加开销。

Auto 的 exact resume 继续刷新 Skill 快照和 MCP 绑定，但比较标准目录的 SHA-256，只交付发生变化的目录。空目录撤销仍交付替换说明，变化目录在真实写入边界附到下一次写入（包括恢复提示），避免拖到下一条用户输入。该去重只在已准入的 Auto 恢复中启用；普通恢复维持原目录替换规则。TraeX 自身恢复时追加的 developer 技能说明仍由原生 CLI 管理，不能声称已完全消除。

飞书卡片使用已有 `active_runtime` 通道显示实际运行模型，切换后立即重新发布，新的 `turn_context` 再提供执行器观测。Wrapper、Forge、共享 adopt、直接 RPC、远端后端、durable delivery 和 at-most-once 输入不进行自动容量切换。人工 `/model`、`/new`、`/clear` 优先，停用本 Worker 的池；重新 init/restart 可重新加载设置。

配置在新启动或重启会话时生效。手动 `botmux upgrade` 会覆盖本地热修，需要检查正式版本是否包含此功能。切换仍会影响跨模型提示词缓存；本功能限制切换次数，不能保证缓存保留或 Token 用量下降。

验证包含配置读写与刷新、五模型顺序编辑、阈值和缓冲、白名单、100% 与更低负载的偏好顺序、备选实际排队后继续向后检查、缺失数据、全高负载选择及同值顺序、exact native resume、原输入不重放、新回合恢复首选、卡片模型 IPC、关闭时行为、现有 TraeX type-ahead/隔离重启回归，以及编译二进制与真实 Worker/tmux。
